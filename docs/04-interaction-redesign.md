# 04 · 交互重设计方案 v1

> 背景：现有系统功能链路完整，但交互“单薄”——能点，但缺少反馈、缺少上下文、缺少直接操纵，操作者需要自己脑补系统状态。
> 本方案先审计全部现有操作，再用可执行的交互原则逐一重构，最终形态是“**一画布 + 检查器 + 命令面板**”。

## 1. 问题定义：单薄感的三个根源

| 根源 | 现状 | 体感 |
|---|---|---|
| **反馈缺失** | 点“保存/生成/批准”后界面只是数据刷新，无确认、无动画、无进度、无撤销 | “我点了没有？成功了吗？还能反悔吗？” |
| **上下文缺失** | 看不到“改这里会影响下游哪些环节/花多少钱/多久”，状态徽章含义没解释 | “这个 stale 是什么意思？我要重跑哪些？” |
| **操作割裂** | 同一对象（beat/图层/声线）散落在 6 个页面；大量表单下拉，缺少直接操纵 | “改个说话人要跳来跳去，像填表不像创作” |

## 2. 现有操作全景审计

| # | 操作 | 当前交互 | 单薄点 | 目标交互 |
|---|---|---|---|---|
| 1 | 上传 txt | 表单+按钮，结果文字 | 无拖放高亮/无进度/错误无引导 | 全屏拖放区 + 解析进度条 + 成功进入“下一步”卡片 |
| 2 | 运行单章分析 | 一个按钮，转圈 | 无费用/时间预估，失败只弹红字 | 内联影响预报（约 X tokens / ¥Y / 30s）+ 分阶段进度 |
| 3 | 批准风格方案 | 卡片按钮 | 三方案无对比视图，无“这会影响什么” | 左右分屏对比 + 批准后 toast + 一键撤销 |
| 4 | 运行章节改编 | 按钮 | 同上；红项列表无定位 | 完成后自动跳到第一处红项，红黄项可点击定位原文 |
| 5 | 编辑 beat 台词/情绪 | 表单输入 | 保存无反馈；看不出下游影响 | 保存动画 + “将影响 2 镜头/1 配音”提示 + Cmd+Z 撤销 |
| 6 | 更换说话人 | 编排台表单 / 画布检查器 | 两处入口不一致；改完不知要重跑配音 | 画布 beat 卡内联下拉 + 出现“重配音本句”快捷按钮 |
| 7 | 资产生成 | 两阶段按钮 | 无进度/费用预估；候选单张点选无对比 | 生成队列进度条 + 费用条 + 候选左右键切换对比 + 放大镜 |
| 8 | 批准/淘汰资产 | “选这张”按钮 | 无对比、无撤销、淘汰即消失 | 候选画廊对比 + 撤销 + 标记“待重生成”而非消失 |
| 9 | 构建分镜 | 按钮 | 无 dry-run；失败只有红字 | 构建前显示将产出多少镜头；构建后镜头逐个入场动画 |
| 10 | 改镜头时长/机位 | 表单 | 时间轴无法直接拖 | 画布镜头卡拖右缘调时长；快捷键切换机位 |
| 11 | 换人物图 | 拖资产到镜头 | 已有，但无 ghost/目标高亮/落地反馈 | 拖拽 ghost + 目标镜头发光 + 松手预览 + toast+撤销 |
| 12 | 改入场/出场 | 下拉选择 | 无法直接看到动画边界 | 图层边缘出现“入点/出点”手柄，拖动+选动画类型 |
| 13 | 配音生成/重录 | 按钮+列表 | 无进度（8 句逐句跑）；ASR 红项无引导 | 逐句进度条 + 完成后自动聚焦第一处红项 + 单句重录快捷 |
| 14 | 渲染 | 复制命令到终端 | 门槛高、无进度 | 画布内一键渲染 + 进度条 + 完成后弹片预览播放器 |
| 15 | 重跑节点 | 编排台按钮 + confirm() | confirm 是系统弹窗，信息量低 | 内联确认卡：显示“将覆盖 N 个下游产物、预计费用 Y”+ 可勾选只重跑下游 |
| 16 | 看成本 | 终端命令 | 无图形 | 画布左上角成本仪表盘（今日/本书/节点） |
| 17 | 全部状态含义 | 英文徽章 draft/stale | 无解释 | 统一中文徽章 + tooltip + stale 显示影响范围 |

## 3. 设计原则（调研归纳）

1. **每个动作必须有反馈**（Apple HIG：visible response；异步任务用确定性进度条，不确定用活动指示器）。
2. **撤销优于确认弹窗**（HIG：破坏性操作可逆时，Undo 比 “Are you sure?” 更好）——我们的核心操作全部可逆，应默认无 confirm，改为一键 Undo。
3. **直接操纵优先**（Direct Manipulation：所见即所得、对象-动作、即时可见结果）——画布上拖图、拖时长、拖入出点，比表单更符合“编排”。
4. **渐进披露**（HIG：先给核心，细节按需展开）——默认视图只有高频操作；高级 JSON/机位参数收进“高级”折叠。
5. **空间一致性（一个家）**——所有对象以“画布”为唯一中枢，检查器/命令面板是工具；现有 6 个页面降级为画布的“详细视图”。
6. **AI 操作必须有 feedforward**（成本/耗时/影响范围预报）——AI 工具的独有原则：按按钮前让人知道将发生什么，生成后给 diff 而不是覆盖感。
7. **微交互要成体系**——统一的时长/缓动：确认 200ms、面板 250ms、对象级动画 300–400ms；加载用骨架屏，完成用 checkmark 动画。
8. **键盘可达**——高频编排动作给快捷键（见 §5），因为画布工作的瓶颈是“手离开鼠标去找按钮”。

## 4. 核心交互模式库（本项目的实现清单）

| 模式 | 实现 | 覆盖问题 |
|---|---|---|
| 全局 Toast | 右上角栈式 toast：成功（自动消失+undo 入口）/失败（可复制详情）/进行中（可点击跳转） | 反馈缺失 |
| **快照撤销** | 每次保存/生成前把受影响的表行 JSON 存入 `snapshots` 表；Toast 提供“撤销”，支持多级 Cmd+Z | 可逆性 |
| 影响预报 | 写一个 `estimate(node, book)` 返回“将覆盖 X、预计消耗 Y tokens/图、约 Z 秒”；所有 AI 按钮 hover/点击后内联展示 | 上下文缺失 |
| 内联确认卡 | 替换 `confirm()`：对象内弹出“影响范围 + 预估 + [执行] [取消]”，不打断空间感 | 单薄弹窗 |
| 状态徽章体系 | 五色统一：approved 绿 / draft 灰 / pending_review 蓝 / stale 红（含“影响 N 个下游”）/ rejected 灰划线；全站中文 | 状态不可读 |
| 空状态引导卡 | 无数据页面显示“下一步该做什么 + 一键执行”卡片链 | 冷启动 |
| 骨架屏/进度 | 分析/改编/资产/配音接 jobs 进度轮询，按钮变进度条 | 等待焦虑 |
| 拖放反馈套件 | ghost 预览、目标镜头发光、落下脉冲、错放抖动提示 | 拖拽体感 |
| 命令面板 Cmd+K | 输入“换声线/重跑分镜/打开成本/跳到 beat 3”即达 | 操作割裂 |
| 微动画 | 保存 checkmark 200ms；节点 stale 红框呼吸 1s 后静止；镜头卡进入逐帧 stagger | 单薄感 |
| 键盘快捷键 | 画布：`1-6` 切换签核层、`B` 选 beat、`S` 选镜头、`D` 复制资产、`R` 重跑当前、`Cmd+Z` 撤销 | 效率 |

## 5. 目标形态：一画布 + 检查器 + 命令面板

```
┌ 左侧：流程铁路（6 个签核点，状态灯）┐
│ A 档案 ●  B 脚本 ●  C 资产 ● …      │
└──────────────────────────────────┘
┌──────────── 画布（中枢）────────────────────┐ ┌ 右侧：检查器 ┐
│ 资产池 │ beat 轨道 / 镜头轨道 / 声音轨道     │ │ 所选对象     │
│（可拖）│ 拖图换人 · 拖边缘改时长 · 拖入出点  │ │ 表单+高级JSON │
└───────────────────────────────────────────┘ └──────────────┘
┌ Cmd+K 命令面板（随时唤起）┐   ┌ 成本仪表盘 ┐
└──────────────────────────┘   └────────────┘
```

- 现有 6 个页面保留为“详细视图”，但从画布一个入口可达；
- 上传/分析/风格选择作为“流程铁路”的第一步引导；
- 任何 AI 动作：先预报 → 执行 → 进度 → diff/撤销。

## 6. 三个核心任务的理想剧本（重构前后对比）

### 场景 1：把第 3 句从旁白改成林晚
- 现在：去编排台 → 找到 beat#3 → 下拉 → 保存 → 回画布 → 重跑配音。
- 目标：画布点 beat#3 → 检查器下拉“林晚” → 保存（checkmark+影响提示“1 句配音待重录”）→ beat 卡上出现「重配音本句」按钮 → 点击 → 该句进度条 2s → 🔊 变绿。**全程不出画布，4 步 1 屏。**

### 场景 2：给林晚换一张表情并让她从右滑入
- 现在：拖图（无反馈）→ 检查器下拉入场 slide_right → 保存。
- 目标：拖图 → 目标镜头发光 → 松手 ghost 落入 + Toast「已替换，Cmd+Z 撤销」；图层边缘出现**入点手柄**，拖到 0.5s 处 → 手柄旁弹动画选择器选 slide_right → 画布上立即播放 0.5s 预览动画。

### 场景 3：重跑分镜（覆盖 17 镜头）
- 现在：按钮 → confirm() → 等待 → 刷新。
- 目标：点「重跑分镜」→ 按钮原位展开内联卡：“将重建 17 镜头 · 不消耗 AI · 约 3s · 会覆盖你对镜头的修改（可撤销）”→ [执行] → 镜头逐个 stagger 重新排布 → 完成 toast「已重建，[撤销]」。

## 7. 落地路线（迭代优先级）

| 迭代 | 内容 | 验收 |
|---|---|---|
| **I0 反馈与撤销层（先做）** | Toast 体系、快照表 + Undo、统一状态徽章中文+tooltip、所有按钮 loading/进度态、影响预报函数接入 6 个 AI 按钮、内联确认卡替换 confirm() | 任何操作 ≤1 次点击可撤销；所有异步操作有进度或骨架；无系统 confirm() |
| **I1 画布中枢化** | 流程铁路 + Cmd+K + 成本仪表盘 + 6 页收编为检查器视图 | 换说话人/换图/改出入场都在画布完成，不需跳页 |
| **I2 直接操纵增强** | 拖时长手柄、入点/出点手柄、动画选择器、拖放 ghost/高亮/抖动、键盘快捷键 | 纯鼠标/键盘可完成 80% 高频编排 |
| **I3 AI 建议层** | 基于自检红黄项生成建议 chips（“这 3 镜头节奏单调，自动重排？”）、生成 diff 对比视图 | 红项不再只是列表，而是可一键采纳的建议 |

## 8. 可度量指标

- 换说话人：**4 步 2 屏 → 4 步 1 屏**；
- 错误恢复：**0 次 → 1 次点击（Undo）**；
- 异步操作反馈覆盖：**100%**；
- 用户第一次上传到跑通 A/B 签核：目标 **≤ 3 分钟无文档**；
- 画布内完成的高频任务占比：**≥ 80%**（其余走 Cmd+K）。

> 参考文献：Apple Human Interface Guidelines（反馈/撤销/渐进披露/拖放）、Direct Manipulation 原则、Canva/CapCut/Runway 的 AI 创作工作流实践。
