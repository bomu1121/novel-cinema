# 00 · 产品与技术决策基线

> 这是整个项目的“宪法”。后续所有数据模型、流水线、任务拆分都以本文件为准。
> 任何与本文冲突的设计，要么改本文（记录原因），要么不改设计。

## 1. 产品定位

- **单人创作者工作台（自用 SaaS，单租户）**：面向个人开发者自己做内容，不做多用户、不做私有化部署。
- **AI 干活 + AI 自检 + 人签核**：用户缺乏专业影视/美术知识，所以界面永远给“候选 + 风险报告 + 通过/换一版”，不要求用户手写 prompt 或调复杂参数。
- **一本书 = 一个 master 项目**：内部按“幕（act）”组织，最终渲染整本 1 小时版本；发布时在幕边界确定性切分 15–20 分钟一集。切分是转码，**不重新生成任何 AI 内容**。
- **素材来源**：任意 txt 上传，版权责任归使用者（本项目只做留痕记录）。

## 2. 核心创作决策

| 主题 | 决策 |
|---|---|
| 粒度 | 章节 → 场景 → **beat** → shot。不再是“一两分钟换一张图” |
| 30 万字处理 | 分层记忆：全书档案（Book Bible）→ 章节摘要 → 段落向量检索；两遍处理（全书粗读 + 逐章精做），增量更新 |
| 1 小时成片 | 每章只挑 1–3 个核心 beat 影像化，其余旁白压缩；AI 必须输出**取舍报告**，线索可用旁白/文字卡承载 |
| 生动性 | 背景/人物/表情/姿势做成**分层资产**，入场退场=图层动画，换表情=换 asset，不是重新生成整图 |
| 图像 | 平台内生成为第一公民（保留 prompt/seed/参考图元数据），外部导入为兼容通道，进同一资产库 |
| 配音 | 旁白 + 每角色一个 voice_id，逐句带情绪/语速合成；按角色锁定、跨章复用 |
| 图生视频 | 只用于约 10% 的关键 beat；第一版不碰 ComfyUI、不训 LoRA |
| 推理支持 | 线索账本（出现章/回收章/是否红鲱鱼/剧透标记）+ 时间线 + 剧透规则注入提示词 |
| 通用化 | 线索账本做成可插拔“领域模块”（言情/武侠/历史/科幻各自换模板），主干流水线不变 |

## 3. 技术栈定案

| 模块 | 方案 |
|---|---|
| 应用 | Next.js + TypeScript，单仓库；托管 Vercel/Railway |
| 数据库 | Supabase Postgres + pgvector（不做独立向量库） |
| 存储 | Cloudflare R2 或 S3 兼容 |
| 任务队列 | Inngest / Trigger.dev 托管队列；本地开发提供 `npm run pipeline:local` |
| 渲染 | FFmpeg/Remotion 作为一次性 Cloud Run / Railway Job，渲染完销毁 |
| LLM | 便宜模型做全书粗读；强模型做章节改编/实体合并/自检；**强制 JSON Schema 输出（zod 校验）** |
| 图像 | 首选带“角色参考图”的商业 API（即梦/Seedream 一档）；精细控制用 Replicate/FAL 跑 Flux + IP-Adapter |
| TTS | MiniMax / 火山 / CosyVoice 一档，按角色锁 voice_id，支持情绪/语速 |
| ASR | Whisper API 回读校验台词 |
| 图生视频 | 可灵/即梦/Runway，仅关键 beat |

## 4. 明确不做（v0）

- 不做端到端“txt → 成片”一键黑盒
- 不训自定义 LoRA、不搭 ComfyUI、不部署任何大模型
- 不做多用户、不做计费、不做私有化
- 不追求全片图生视频
- 不在 v0 做整本 30 万字的自动连跑（先单章跑通，M1 再放量）

## 5. 术语

- **Book Bible**：全书档案（人物/关系/地点/物品/时间线/线索/风格圣经）
- **beat**：脚本最小单元，对应一段旁白/一句台词/一个动作/一张文字卡
- **shot**：一个镜头，由背景 + 若干图层 + 机位动效组成
- **asset**：可复用媒体资产（角色设定图/表情/姿势/背景/道具/BGM/SFX）
- **stale**：上游审定内容变更后，下游产物被标记为过期，需要局部重跑
- **签核点（signoff）**：人工把关节点，AI 给出候选与风险报告，人只做通过/换一版/编辑

## 6. 人工投入预期

一部 30 万字小说、1 小时成片：熟练后 **3–6 个晚上**，花在选风格/声线、抽查标红 beat、最终预览，而非专业劳动。
