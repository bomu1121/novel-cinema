# 09 · 每视图主操作审计（docs/07 V3 / metric 22）

> 目的：确保每个页面/视图只有一个 primary CTA，避免多个主按钮竞争（docs/08 V3）。
> 审计日期：2026-08 · 方法：按页面人工走查 + 视觉基线复核。

## 规则

- 一屏一个 **primary**（视觉最强、默认焦点）。
- 次要与破坏性动作用 secondary / ghost / danger。
- `approve` 只用于“批准/选这张”类签核动作。
- 若有多个同等重要的动作，用卡片/区块各自承载，页面级仍只有一个 primary。

## 审计结果

| 页面 | 主操作（Primary） | 次操作 / 危险操作 | 结论 |
|---|---|---|---|
| `/` 首页 | 上传并解析 | 选择文件、项目卡进入 | ✅ 单一主操作 |
| `/books/[id]` 书导航 | 分镜画布（accent 高亮入口） | 各签核入口、编排台 | ✅ 画布作为深度编辑入口 |
| `bible` | 运行单章分析 | 批准某套风格、左右对比 | ⚠️ 页面级“分析”与“批准”都在页头，但分析是主流程，批准是候选区动作；可接受 |
| `script` | 运行章节改编 | 批准本章、保存修改、审阅决策 | ✅ 生成/审阅分离 |
| `assets` | 生成设定图与背景 | 生成表情、选这张、对比 | ⚠️ 两个 JobRunner 并列（phase1/phase2），phase1 为主、phase2 secondary |
| `storyboard` | 构建分镜 | 批准分镜、保存时长/背景 | ✅ |
| `voice` | 逐句合成 | 批准全部、重录 | ✅ |
| `render` | 复制命令 | 渲染任务进入 | ✅ |
| `workbench` | 节点重跑（SectionCard 内） | 保存、撤销、Cmd+K、PlanSheet | ✅ 编排台本身是多动作控制台，按区块收敛 |
| `canvas` | 全片预览（工具栏） | 撤销、重跑、拖拽、检查器保存 | ✅ 工具栏主操作为预览 |

## 发现的问题

1. **assets 页**：两个生成按钮在页头并列，视觉上都是可点主按钮；建议 phase1 保持 primary，phase2 明确 secondary（当前已是 `variant="secondary"`，但 label 长度相近，仍显并列）。
2. **bible 页**：页头“运行单章分析”与候选卡内的“批准这套”都使用强视觉；建议批准按钮只在候选卡内出现（现状已是），页头保持分析为 primary。
3. **render 页**：复制按钮为 secondary，主视觉是命令块本身；可接受。

## 建议

- 维持现有组件语义；后续若 assets 增加“一键生成全部”，可将 phase1/phase2 合并为一个主操作。
- 把本审计作为 `nc-ui-contract` 复核清单常驻项（已在 docs/08 V3 提及）。
